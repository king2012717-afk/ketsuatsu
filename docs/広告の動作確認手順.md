## 1. 広告が出る条件

次の3つがすべて揃ったときだけ、画面上部にバナーが表示されます。揃うまではバナーの View 自体を作らないので、広告のリクエストも出ません。

| # | 条件 | 確認方法 |
|---|---|---|
| 1 | 広告の同意画面で、どちらかを選んだ | 初回起動時の「広告の表示について」の画面 |
| 2 | ATT（「トラッキングを許可しますか」）に回答済み | 同意画面のあとに出る iOS の確認画面 |
| 3 | LevelPlay の初期化が成功した | Xcode のコンソールに `[Ads] LevelPlay 初期化失敗` が出ていない |

同意画面での選択は 設定 →「広告」で切り替えられます（「興味に合わせた広告を表示する」）。

---

## 2. 同意画面と ATT の確認（審査で必ず見られる）

**どちらを選んでも ATT が出ること**を、毎回の提出前に確認します（2026-09-22 うちの美術館の審査差し戻しの再発防止）。

1. アプリを端末から削除する（同意の選択と ATT の状態が初期化される）
2. Xcode から実行し、同意画面で **「興味に合わせた広告を表示する」** を押す → ATT が出ることを確認
3. もう一度アプリを削除して実行し、**「興味に合わせない広告にする」** を押す → ATT が出ることを確認
4. どちらの場合も、ATT に答えたあとでバナーが出ることを確認

---

## 3. バナーが出ないときの切り分け

| 症状 | 原因 | 対処 |
|---|---|---|
| バナーの枠ごと出ない | 同意画面・ATT が済んでいない、または SDK の初期化に失敗 | 同意画面と ATT に回答したか確認。Xcode のコンソールで LevelPlay のログを見る |
| しばらく出ない | 在庫がない（公開前は Not live yet のため起こりやすい） | 読み込み失敗時は 10 → 30 → 60 → 120 → 300 秒の間隔で 5 回まで再試行し、それ以上は試さない。アプリを入れ直すか、Test Suite で確認する |
| アプリを背面に回すと再試行が止まる | 仕様どおり（仕様書 1-10） | 前面に戻ると再試行を再開する |

---

## 4. LevelPlay Test Suite を使う

在庫の有無に左右されず、各ネットワークの広告表示を確認できます。
Unity ダッシュボードで対象端末をテストデバイスに登録しておく必要があります。

Test Suite を呼ぶコードはアプリに入っていません。必要になったら、
SDK 初期化後に次の1行を一時的に足して確認し、**確認後は必ず消してください。**

```swift
LevelPlay.launchTestSuite(viewController)
```
